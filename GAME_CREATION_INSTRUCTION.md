# Техническое задание для ИИ: игра «I Spy With My Little Eye» в HTML

## 1. Цель

Создай законченную детскую браузерную игру **«I Spy With My Little Eye»** на основе приложенной картинки с лесной поляной. Игра должна работать локально после открытия `index.html`, без сервера, сборщика, npm и интернет-соединения.

Игрок видит картинку и задание на английском языке:

> **I spy with my little eye something... yellow!**

Последнее слово — случайно выбранный цвет из списка:

- `yellow`
- `red`
- `pink`
- `orange`
- `blue`
- `white`
- `brown`
- `purple`

Игрок нажимает на предмет нужного цвета. При неверном выборе звучит короткий звук ошибки. При верном выборе открывается окно со случайной английской буквой, которую ребёнок должен назвать вслух. После закрытия окна найденный предмет становится чёрно-белым и получает хорошо заметный крестик, а игра показывает следующее задание.

## 2. Исходное изображение

Используй файл:

`Gemini_Generated_Image_dk6qjvdk6qjvdk6q.png`

Оригинальный размер изображения: **1408 × 768 px**, соотношение сторон примерно **1.833 : 1**.

Для проекта положи копию изображения сюда:

`assets/scene.png`

Не перерисовывай фон и не заменяй его похожей иллюстрацией. Не обрезай изображение. Оно должно целиком помещаться в игровую область с сохранением пропорций.

## 3. Результат, который должен создать ИИ

Структура проекта:

```text
ispy-game/
├── index.html
├── styles.css
├── script.js
└── assets/
    └── scene.png
```

Допускается один автономный `index.html` со встроенными CSS и JavaScript, но предпочтительнее разделить файлы. Не используй React, Vue, Canvas-фреймворки и внешние CDN. Используй только HTML5, CSS3, SVG и чистый JavaScript.

## 4. Интерфейс

### Верхняя панель

Над картинкой размести крупную карточку задания:

```text
I spy with my little eye something... YELLOW!
```

Требования:

- фраза всегда на английском языке;
- название цвета написано прописными буквами;
- слово цвета окрашено соответствующим цветом, но имеет контрастную обводку или подложку;
- текст легко читается детьми;
- рядом можно показать прогресс: `Found: 3 / 24`;
- задание нельзя менять отдельной кнопкой, пока на сцене остаётся хотя бы один доступный предмет текущего цвета.

### Игровая сцена

- Картинка центрируется и масштабируется через `width: 100%; height: auto`.
- Над картинкой располагается прозрачный SVG с `viewBox="0 0 1408 768"`.
- SVG должен масштабироваться строго вместе с изображением.
- Каждый игровой предмет имеет отдельную прозрачную активную область: `circle`, `ellipse`, `rect`, `polygon` или `path`.
- Активная область не должна быть видимой в обычном состоянии.
- При наведении мышью допустимо лёгкое свечение или изменение курсора, но нельзя подсказывать цвет ответа.
- На сенсорном экране минимальная удобная зона нажатия — около 40 × 40 CSS-пикселей. При этом соседние зоны не должны заметно перекрываться.

Не определяй цвет предмета по пикселю, на который нажал игрок. У каждого объекта должны быть заранее записаны `id`, `color` и SVG-геометрия.

### Модальное окно с буквой

После правильного нажатия открой модальное окно поверх затемнённой сцены:

- крупная случайная буква английского алфавита `A–Z`;
- короткая надпись `Name this letter!`;
- кнопка закрытия `×` в правом верхнем углу рамки;
- окно не закрывается кликом по затемнённому фону, чтобы ребёнок не пропустил букву случайно;
- закрытие возможно кнопкой `×` и клавишей `Escape`;
- крестик — настоящая кнопка с `aria-label="Close"`, а не просто символ;
- при открытом окне фокус переводится на кнопку закрытия;
- фон под окном недоступен для кликов.

Буква выбирается случайно при каждом правильном ответе. Желательно не показывать одну и ту же букву два раза подряд.

## 5. Интерактивные предметы и цвета

Создай массив объектов примерно такого вида:

```js
const objects = [
  {
    id: "sun",
    color: "yellow",
    label: "sun",
    shape: "circle",
    coords: { cx: 246, cy: 83, r: 64 },
    found: false
  }
];
```

Включи как минимум следующие хорошо различимые предметы. Координаты ниже ориентировочные; уточни контуры по изображению, не меняя смысл предметов.

| Цвет | Предметы на картинке |
|---|---|
| yellow | солнце, жёлтые груши, жёлтые цветы на траве |
| red | красные яблоки, красные цветы внизу, красные цветы около деревьев |
| pink | розовая птица, малина, клубника, розовые бабочки, розовые цветы |
| orange | белка, оранжевая рыба, оранжевая бабочка |
| blue | синяя птица, синяя рыба, голубая бабочка, черника, стрекоза |
| white | облака, белые участки на сове, белые крылья стрекозы; не считай фон неба и блики воды |
| brown | ствол большого дуба, жёлуди, сова, орех в лапах белки; крупный ствол можно считать одним объектом |
| purple | фиолетовая рыба, ежевика, фиолетовые бабочки |

Правила разметки:

1. Каждый отдельный фрукт, цветок, желудь или животное может быть самостоятельным объектом.
2. Для первого варианта игры достаточно **24–40 активных предметов**. Не обязательно размечать абсолютно все ягоды и листья.
3. Выбирай предметы с однозначным доминирующим цветом.
4. Не делай активными траву, небо, воду и большие области фона.
5. Один объект относится только к одному цвету.
6. Белые области размечай особенно аккуратно: кликабельным должен быть конкретный предмет, а не пустой участок картинки.
7. Если зона объекта сложная, используй `polygon` или `path`, а не огромный прямоугольник.
8. У каждой области должны быть `data-id`, `data-color`, `role="button"`, `tabindex="0"` и понятный `aria-label`, например `Select apple`.

Для точной настройки координат добавь в код константу `DEBUG = false`. При `DEBUG = true` активные SVG-области должны становиться полупрозрачными, получать контур и показывать `id` объекта. При `false` отладочная разметка полностью скрыта.

## 6. Игровая логика

### Начало игры

1. Дождись загрузки изображения.
2. Создай SVG-области из массива объектов.
3. Случайно выбери цвет только из тех цветов, для которых существует хотя бы один ненайденный объект.
4. Покажи первую фразу.

### Неверный ответ

Если `clickedObject.color !== currentColor`:

- проиграй короткий характерный звук ошибки;
- слегка встряхни карточку задания или выбранную область;
- не открывай модальное окно;
- не помечай предмет найденным;
- не меняй текущий цвет;
- не блокируй предмет после ошибки.

### Верный ответ

Если `clickedObject.color === currentColor`:

1. Сразу временно заблокируй повторные клики.
2. Запомни выбранный объект как `pendingObject`.
3. Проиграй короткий приятный звук успеха.
4. Выбери случайную букву `A–Z`.
5. Открой модальное окно с буквой.
6. Пока окно открыто, ещё не запускай следующий вопрос.

### Закрытие окна

После нажатия на `×` или `Escape`:

1. Закрой окно.
2. Установи `pendingObject.found = true`.
3. Отключи hit-area найденного предмета (`pointer-events: none`, убрать из tab order).
4. Наложи на предмет локальный эффект чёрно-белого изображения и крестик.
5. Обнови счётчик.
6. Если остались предметы — случайно выбери следующий доступный цвет и обнови задание.
7. Сними блокировку кликов.
8. Если предметов не осталось — покажи финальный экран.

Следующий цвет выбирай из множества цветов, у которых остались ненайденные предметы. По возможности не повторяй тот же цвет два задания подряд, если доступны другие цвета.

### Нажатие на найденный предмет

Найденный объект больше не является активным. Нажатие на его крестик или обесцвеченную область ничего не делает и не воспроизводит звук ошибки.

## 7. Как сделать предмет чёрно-белым

Нельзя применять `filter: grayscale(1)` ко всей исходной картинке: это обесцветит всю сцену. Для каждого найденного объекта создай локальный SVG-фрагмент:

1. В `<defs>` объяви фильтр `grayscale` через `feColorMatrix`.
2. Создай `<clipPath>` по геометрии найденного объекта.
3. Поверх основной картинки добавь ещё один `<image>` с тем же `assets/scene.png`.
4. Применяй к этой копии `clip-path` конкретного объекта и фильтр grayscale.
5. Поверх центра объекта нарисуй контрастный крестик из двух линий.

Пример фильтра:

```html
<filter id="grayscale-filter">
  <feColorMatrix type="saturate" values="0" />
</filter>
```

Крестик должен иметь тёмную внешнюю обводку и светлую или красную внутреннюю линию, чтобы быть видимым и на светлом, и на тёмном фоне. Он не должен закрывать соседние предметы.

Если локальное обесцвечивание получается технически нестабильным, допустимый запасной вариант — оставить исходный цвет и показать на найденном объекте полупрозрачную серую маску с крестиком. Не обесцвечивай прямоугольную область вокруг предмета.

## 8. Звуки

Не подключай внешние аудиофайлы. Сгенерируй короткие звуки через Web Audio API:

- ошибка: два коротких низких нисходящих тона;
- успех: два коротких приятных восходящих тона.

Создавай или возобновляй `AudioContext` только после первого пользовательского действия, иначе браузер может заблокировать звук. Добавь кнопку-переключатель звука с состояниями `Sound on` / `Sound off`, доступную с клавиатуры. Звуки не должны быть громкими, резкими или длиннее примерно 0.5 секунды.

## 9. Случайность и состояние

Используй `Math.random()`:

```js
function randomItem(items) {
  return items[Math.floor(Math.random() * items.length)];
}
```

Храни состояние явно:

```js
const state = {
  currentColor: null,
  pendingObjectId: null,
  lastLetter: null,
  inputLocked: false,
  soundEnabled: true,
  foundIds: new Set()
};
```

В первой версии не сохраняй прогресс между перезагрузками: обновление страницы начинает новую игру. Перемешивай последовательность цветов и букв.

## 10. Финал и перезапуск

Когда все размеченные предметы найдены:

- покажи сообщение `Great job! You found everything!`;
- отобрази количество найденных предметов;
- проиграй короткую победную мелодию;
- покажи кнопку `Play again`;
- после `Play again` сбрось `found`, маски, крестики, счётчик, букву и текущее задание без перезагрузки страницы.

## 11. Адаптивность

Игра должна корректно работать:

- на экранах от 360 px по ширине;
- на планшетах;
- на настольных компьютерах;
- мышью, касанием и клавиатурой.

Важное правило: изображение и SVG-overlay находятся в одном контейнере с `position: relative`, занимают одинаковые координаты и имеют одинаковое соотношение сторон. SVG размещается через `position: absolute; inset: 0; width: 100%; height: 100%`.

На узком портретном экране допускается горизонтально ориентированная картинка во всю доступную ширину. Не растягивай её по вертикали. Карточка вопроса и кнопка звука должны оставаться видимыми.

## 12. Доступность и безопасность взаимодействия

- Все кнопки имеют видимый `:focus-visible`.
- Кликабельные SVG-объекты активируются `Enter` и `Space`.
- Модальное окно имеет `role="dialog"`, `aria-modal="true"` и связанный заголовок.
- Не используй только цвет для обозначения результата: успех сопровождается звуком, окном и крестиком.
- Запрети выделение картинки и перетаскивание изображения.
- Используй `touch-action: manipulation` для интерактивных элементов.
- Учитывай `prefers-reduced-motion`: отключай встряхивание и лишние анимации.

## 13. Визуальный стиль

Стиль должен подходить яркой детской иллюстрации:

- округлый, дружелюбный шрифт с системным fallback;
- светлая карточка вопроса с мягкой тенью;
- крупные элементы управления;
- плавное появление модального окна;
- без сложных меню и лишних инструкций на экране;
- буква в модальном окне занимает основную часть рамки и видна с расстояния.

Не добавляй поверх картинки постоянные подписи предметов и не показывай границы hit-area в рабочем режиме.

## 14. Рекомендуемая архитектура JavaScript

Раздели логику на небольшие функции:

```js
initGame();
renderHotspots();
chooseNextColor();
handleObjectSelection(objectId);
playErrorSound();
playSuccessSound();
chooseRandomLetter();
openLetterModal(letter);
closeLetterModal();
markObjectAsFound(objectId);
renderFoundOverlay(object);
updateProgress();
showWinScreen();
resetGame();
```

Не смешивай координаты объектов с обработчиками событий. Все данные сцены должны находиться в одном массиве. Используй делегирование событий на SVG или единый обработчик при создании областей.

## 15. Критерии приёмки

Готовая игра считается выполненной, если:

1. Открывается локально двойным кликом по `index.html`.
2. Показывает исходную картинку целиком и без искажений.
3. Выдаёт случайное задание с одним из восьми заданных цветов.
4. На картинке есть не менее 24 отдельных активных объектов.
5. Неверный цвет воспроизводит звук ошибки и не меняет вопрос.
6. Верный цвет воспроизводит звук успеха и открывает окно со случайной буквой `A–Z`.
7. У окна есть рабочая кнопка `×`.
8. После закрытия найденный предмет локально обесцвечивается или покрывается серой маской и получает крестик.
9. Найденный предмет невозможно выбрать повторно.
10. После закрытия окна появляется новое корректное задание.
11. Цвет без оставшихся предметов больше не выпадает.
12. После нахождения всех объектов появляется финальный экран и рабочая кнопка перезапуска.
13. Масштабирование окна не смещает кликабельные зоны относительно картинки.
14. Игра работает мышью, касанием и клавиатурой.
15. В консоли браузера нет ошибок.

## 16. Проверка перед сдачей

Перед завершением проекта выполни ручной тест:

1. Включи `DEBUG = true` и проверь совпадение каждой области с предметом.
2. Проверь по одному правильному и неправильному клику для каждого из восьми цветов.
3. Проверь, что нельзя кликать по сцене при открытом окне с буквой.
4. Проверь закрытие окна через `×` и `Escape`.
5. Проверь, что следующий вопрос создаётся только после закрытия окна.
6. Проверь последний предмет и финальный экран.
7. Нажми `Play again` и убедись, что все предметы снова цветные и активные.
8. Измени ширину окна от 360 до 1400 px и убедись, что hit-area не смещаются.
9. Проверь игру с выключенным звуком.
10. Верни `DEBUG = false` перед сдачей.

## 17. Итоговая команда для ИИ-разработчика

Создай все файлы игры полностью, а не отдельные фрагменты. Самостоятельно разметь активные предметы на исходном изображении в координатах SVG `1408 × 768`. После генерации кода проверь синтаксис JavaScript, пути к ресурсам и соответствие всем критериям приёмки. Не оставляй `TODO`, пустые обработчики и демонстрационные заглушки.
